第 5 章　脚手架进化：工具、代码与记忆

本章讨论提示模板、工具集、控制流、记忆和技能库等脚手架组成部分的更新。案例包括 ReAct、Reflexion、Voyager、MemGPT 与 SWE-agent，分别涉及行动与推理交替、失败反思、技能保存、上下文管理和代理计算机接口。各研究使用不同任务和评估方法，结果不能直接按单一指标横向比较。本章还区分由人工设定更新规则的系统与能够修改自身脚手架的系统；后者见第 6 章。

5.1 脚手架更新与模型参数更新

图 5-1 根据综述 arXiv:2507.21046 整理可更新的系统组成部分。除模型权重外，提示、工具、记忆和代理间的控制关系也可能成为更新对象。脚手架 \(S\) 可在不更新模型权重的情况下修改。不同配置会影响给定任务中的系统表现，实际效果取决于模型、工具和评测设置。技能和程序通常依赖任务及接口，其跨领域迁移能力需要单独评估。模型权重与脚手架更新的成本、持久性和迁移范围应分别分析。第 6 章讨论同时涉及系统代码和改进过程的研究。

5.2 ReAct：推理与环境交互

ReAct（arXiv:2210.03629）交替生成推理步骤、执行动作并接收环境观察，再据此调整后续推理和行动。论文在 HotpotQA、FEVER、ALFWorld 和 WebShop 等任务中与相应基线比较。在 HotpotQA 和 FEVER 的部分设置中，调用 Wikipedia API 提高了回答的事实依据，并减少了观察样本中的幻觉；HotpotQA 分析也显示 ReAct 存在重复行动和无效检索等错误。ALFWorld 与 WebShop 实验报告其相对相应行动或模仿学习基线的成功率提升。推理、行动和观察轨迹便于检查执行过程，但可解释性和人工干预效果仍取决于记录完整度与任务设置。

用五元组表示，ReAct 的控制过程由 \(\text{Thought}_t \to \text{Action}_t \to \text{Observation}_t\) 构成。后续系统在此基础上加入反思（Reflexion）、技能检索（Voyager）或搜索分支（LATS，4.4 节）。在这些方法中，模型权重 \(M\) 保持不变，更新发生在提示、状态、工具或控制流程中。

5.3 Reflexion：基于语言反思的经验更新

基于参数优化的强化学习方法利用交互反馈更新策略参数。Reflexion（arXiv:2303.11366）则将失败轨迹和任务反馈整理为文本反思，写入情景记忆 \(m_t\)，并在后续尝试中将其加入提示。系统由执行任务的 Actor、生成反思的模块和保存反思记录的记忆组成：

\[ m_{t+1} = m_t \oplus \operatorname{Reflect}(\pi_\theta,\, \tau_t,\, \text{feedback}_t), \qquad o_{t+1} \sim \pi_\theta(\cdot \mid q,\, m_{t+1}). \]

论文在 HumanEval、AlfWorld 和 HotPotQA 的特定设置中报告了相对基线的提升。结果受模型版本、提示、样本数量和评估协议影响，不能直接外推为 Reflexion 在其他任务上的优势。反馈可以来自单元测试等外部程序，也可以来自模型生成的反思；后者需要独立检查其准确性。

Reflexion 将语言化反思保存在当前任务的多次尝试之间；相关记忆是否跨任务保留取决于具体实现。Voyager 通过技能库保存可复用程序并在后续任务检索。记忆持久性与改进算子是否更新属于不同维度，递归程度需根据候选生成和选择过程判断。

5.4 Voyager：可执行技能的保存与复用

Voyager（arXiv:2305.16291）是一种面向 Minecraft 的语言模型具身代理，包含三个核心模块：(i) 自动课程：根据探索目标和当前能力生成后续任务；(ii) 技能库：将成功获得的技能表示为可执行 JavaScript 程序并保存，在后续任务中检索和组合；(iii) 迭代提示：结合环境反馈、程序执行错误和自我验证结果修改技能代码。原论文实验使用 GPT-4，未进行模型微调。

Voyager 将技能保存为可执行代码，并通过检索在后续任务中调用。代码可组合，但执行成功只说明程序在当前条件下运行，不代表它能正确处理所有相关任务。论文报告了独特物品数量、探索距离和科技树里程碑等指标相对基线的提升，并测试了技能在新任务中的迁移。应结合原论文中的环境、基线和评估条件理解这些数字。

5.5 MemGPT：基于分层存储的上下文管理

上下文窗口限制了单轮输入中可直接使用的信息量。MemGPT（arXiv:2310.08560）借鉴操作系统的分层存储设计，通过函数调用管理上下文内外的信息，并根据任务需要调入或移出对话历史与文档内容。论文评估了超长文档分析和跨会话聊天等任务。不同系统采用的检索、摘要和记忆更新机制各异，应结合具体实现比较。

MemGPT 中，模型依据任务状态参与上下文内容的选择和管理。该过程改变运行时可用的信息，但不必然涉及模型参数或记忆管理规则更新。第 6 章讨论的 SICA 则将包含代理逻辑的代码库纳入自动修改范围。

5.6 SWE-agent：面向语言模型代理的计算机接口设计

SWE-agent（arXiv:2405.15793）研究面向语言模型代理设计计算机接口。代理与人类用户在操作模式、状态管理和错误恢复能力方面存在差异，直接使用面向人类开发者设计的 Shell 和 Vim 可能增加输出处理、光标定位和文件编辑错误。论文设计的代理计算机接口（Agent-Computer Interface，ACI）提供文件查看与编辑命令、自动 lint 和适合截断的输出格式，以提高文件创建、编辑、导航和测试执行的可靠性。论文在其评测设置中报告 SWE-bench pass@1 为 12.5%、HumanEvalFix 为 87.7%；对照实验显示，仅调整提示而不修改接口带来的性能变化较小。上述数值受模型、基线和评测协议限制。

论文还报告 pass@k，用于估计从 \(n\) 个候选中抽取 \(k\) 个时至少有一个通过测试的概率。对于单个任务，若 \(c\) 个候选通过测试，其无放回抽样估计为

\[ \widehat{\operatorname{pass@}k} = 1-\frac{\binom{n-c}{k}}{\binom{n}{k}}, \qquad 0\le c\le n,\quad 1\le k\le n. \]

基准分数通常在多个任务上按该估计汇总。pass@k 反映候选采样和测试规则下的通过情况，不代表候选的部署质量，也不能与 ACI 的单次成功率简单相乘为系统能力。比较结果时需报告任务集、采样预算、测试规则和独立评估结果。

5.7 脚手架更新规则的自动修改

上述系统的反思模板、课程规则、上下文管理方式或代理接口由研究者设定。系统可在这些规则下积累状态或改进任务表现，但产生更新的规则本身通常没有随之更新。SICA、ADAS 和进化搜索等方法进一步探索了系统代码或代理架构的自动修改（第 6 章）。评估这类方法时，需要单独说明候选生成、验收、留出测试和回滚方式。

5.8 小结

本章案例展示了通过提示、工具、记忆、技能库和接口设计改变代理行为的不同方法。这些方法通常不更新模型权重，但其效果仍依赖任务、模型和评估协议。所讨论的更新规则大多由研究者设定；第 6 章进一步分析系统自动修改代码或搜索代理架构的研究，并讨论相应的验收条件。
