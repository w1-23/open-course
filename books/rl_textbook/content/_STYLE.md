# 写作与排版规范（12 章版，作者必读）

本文件是写作契约。每位作者只写两个文件：`content/chNN.md`（正文）与
`figures/chNN_figs.py`（插图脚本，matplotlib → SVG）。

**不要修改引擎文件**（`config.py`、`md2html.py`、`prepare.py`、`render.py`、`layout.py`、
`mathjax.py`、`frontmatter.py`、`main.py`、`figkit.py`、`verify.py`、`check_content.py`）。
需要新版式能力时给 lead 发消息，不要自己改。

**样板章**：`content/ch02.md` 与 `figures/ch02_figs.py` 已封版，是格式与深度的基准。动笔前先通读。

## 1. 目录

```
content/chNN.md           正文（你写）
content/_CONVENTIONS.md   符号与术语约定（必读，不得违反）
figures/chNN_figs.py      插图脚本（你写）
figures/out/*.svg         脚本输出，不要手工编辑
source/text/*.txt         已抽取的文献正文，引用时据此核对，不要凭记忆
```

## 2. 构建与自检

```bat
python figures\chNN_figs.py       :: 先出图
python main.py --only N           :: N = 1..12
python check_content.py --only N  :: 必须 0 问题
python verify.py                  :: 本章那行必须全零
```

预览几页：`python -c "import fitz;d=fitz.open('output/03_DP与TD.pdf');d[7].get_pixmap(dpi=110).save('cache/p8.png')"`

## 3. 文件头

```markdown
---
title: 动态规划、蒙特卡洛与时序差分
no: 3
---
```

`no` 与章号一致，`title` 与 `config.CHAPTERS` 中的标题逐字一致。

## 4. 章节结构

每章 4–6 个 `##` 大节 + 四个收尾节（标题逐字）：

```markdown
## 3.1 第一节标题
### 3.1.1 小节标题
## 3.2 ……
## 本章小结
## 关键公式
## 习题
## 延伸阅读
```

`##` 自动另起一页，故不要过多；四个收尾节不另起页。`###` 只用于并列子主题，不嵌套四级。
每章 19–22 页（约 17000–21000 汉字）。

## 5. 公式（最易出错）

- 行内 `\(a_t\)`。**禁止 `$...$`**、禁止 `\label`/`\ref`/`\eqref`。
- 独立公式**前后都要空行**，公式内部用 `\tag{N.k}` 编号：

```markdown
由式 (3.2) 可得

\[
V^\pi(s)=\sum_a \pi(a\mid s)\Bigl[r(s,a)+\gamma\sum_{s'}P(s'\mid s,a)V^\pi(s')\Bigr]
\tag{3.3}
\]

其中 \(\gamma\) 是折扣因子。
```

缺任一侧空行，pandoc 会当成行内数学：编号丢失、公式缩小、句子被撕开。
自检/修正：`python scripts\fix_display.py content\chNN.md`。

- 编号从 `\tag{3.1}` 起连续，不跳号不重号；引用写「式 (3.3)」。
- 多行公式用 `aligned`，整块只标一个 `\tag`。公式内不写中文。
- 每个定理/命题/误差界后必须标理论地位：**[精确]、[渐近]、[近似]、[经验规律]**。
  无定理支持时不得使用无条件的「收敛」「稳定」「保证」。

## 6. 图

- 每章 4–6 幅，全部由 `figures/chNN_figs.py` 用 `figkit` 画 SVG；不截图、不外链。
- 图题在 `![...]` 方括号内，以「图 N-k 」开头，编号连续。
- 数据图必须真算（图注写种子、样本量、评估协议），不得用示意曲线冒充实验。
- 结构图用 `figkit.blank` + `figkit.box` / `figkit.arrow`；调色板 `C0..C4`、`INK`、`GREY`；字号 6.6–8.0。
- **对数轴必须显式设置刻度与 ASCII 标签**：matplotlib 默认对数刻度会写出真减号 U+2212，
  宋体子集无此字形，PDF 里变成空方框。用 `ax.set_yticks([...]); ax.set_yticklabels(["1e-4",...])`。

## 7. 表

三线表，表题写在表格**下方**的冒号行（源文件顺序如此；引擎会把它渲染到表格**上方**，
这是排印惯例，作者不必调整）：

```markdown
| 算法 | 方差 | 偏差 |
|:--|:--|:--|
| MC | 高 | 无 |
| TD | 低 | 有 |

: 表 3-1 MC 与 TD 的偏差—方差权衡。
```

表题以「表 N-k 」开头、编号连续；表格不得作为大节的最后一个元素（后面至少再写一段）。

## 8. 框

```markdown
::: def 定义 3.1（策略）
正文……
:::

::: thm 定理 3.2（收敛性 [精确]）
……
:::

::: algorithm 算法 3-1 值迭代
````
1: 输入 V_0
2: for k = 0, 1, 2, ...
````
:::
```

类型：`def`、`thm`、`prop`、`algorithm`、`note`、`warn`、`example`。标题写在 `:::` 行；
伪代码用**四个反引号**围栏；算法框内可用中文（引擎用宋体）。

**独立公式不要放进框里。** MuPDF 排版时会把框拦腰切开：标题与陈述留在上一页（下边框消失），
公式连同只剩竖边框的空壳落到下一页，被切开的那一页往往只剩一两行字。写法是框内只放陈述，
公式紧跟框后用正文引出：

```markdown
::: thm 定理 2.3（残差界 [精确]）
在有限折扣 MDP 中，最优 Bellman 算子的残差给出如下界。
:::

\[
\|V-V^\star\|_\infty \le \frac{\|V-T^\star V\|_\infty}{1-\gamma}
\tag{2.21}
\]

其中 \(T^\star\) 为最优 Bellman 算子，\(\|\cdot\|_\infty\) 是上确界范数。
```

第 1 章按此改写六个框后，页数从 21 页降到 17 页——省下的四页全是框被切开留下的空白。
框内的行内公式（`\(...\)`）不受影响，可以照写。

## 9. 交叉引用

章 `第 4 章`；节 `第 4.3 节`；式 `式 (4.2)`；图 `图 4-1`；表 `表 4-1`；算法 `算法 4-1`。
只引用**已存在**的编号，写前用 `grep` 在 `content/` 确认目标节号存在。

## 10. 篇幅与语气

- 开头 2–3 段交代：本章解决什么问题、与前后章关系、结论的理论地位。
- 每节至少一处「为什么这样做」的动机，不写成算法清单。
- 「延伸阅读」4–6 条，指向 `source/text/` 的文献并写章节号。
- 不用「显然」「众所周知」跳过推导；不用营销式形容词。

## 13. 禁用表述（会被审查判错）

- 「自举低方差且无偏」——低方差与无偏不能无条件同时成立；
- 「PPO 的 clip 保证信赖域」——clip 是启发式，不是信赖域证明；
- 「DPO 与 RLHF 等价」——只在特定 KL 正则目标与偏好模型下等价；
- 「线性函数逼近通常收敛」——off-policy + 自举 + 函数逼近可以发散；
- 「GRPO 就是 PPO 去掉 critic」——还有组内标准化、长度归一化与粗粒度信用分配；
- 「Bellman loss 小 ⟹ 价值接近最优」——三类 Bellman 误差不可互换。

涉及上述话题时按 `content/_CONVENTIONS.md` 的写法给出条件。

## 14 工程约定（2026-10-20 增补，写前必读）

**无章号的条目。** 第 0 章（全书导航）与「第四部分预备」不占章号：它们的 `no` 是 `0` 与 `95`，
正文里**不要**出现「第 0 章 / 第 95 章」字样，章名由 `config.CHAPTERS` 的 `label` 字段给出，
引擎会自动把它写进页眉、页脚、书签与目录。第 0 章的各节不强制换页（`all_tight`），因为它只有
十几页，逐节换页会造出近空白页。

**分节与页数的关系。** 每个 `##` 默认强制换页，所以**页数主要由分节与不可分割块的落位决定，
而不是字数**。删掉 300 字反而可能多出一页；要压页，压的是「某一节末尾溢出到下一页的那 2–3 行」，
不是随便删句子。压缩时先看 `verify.py` 的 `thin` 列，它给出正文少于 300 字且没有大图的页号。

**静默丢页。** MuPDF Story 在某些版面流下会**整页丢掉正文与公式**，PDF 文本层里查不到，
`verify.py` 五项仍全零。构建日志里的 `!! 正文可能丢失`（阈值 99.5%）与 `!! N 个公式未渲染`
是唯一的信号。看到这两条中的任何一条：① 数页数有没有少一页；② 在 PDF 里搜该节关键词；
③ 最省事的修法往往是把触发点附近的一句话改短或改长一句，然后重建。

**改 md 只用编辑器或 Python 脚本。** PowerShell 的 `Set-Content -Encoding utf8` 会写 BOM，
构建会报 `front matter block missing`。同理，不要用 PowerShell 的 heredoc 传多行 Python。
