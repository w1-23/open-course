# CH07-SEC-001 背景规划与决策时规划没有分开

对象：`content/ch07.md:20`（`搜索控制` 的定义）与 `content/ch07.md:171-175`（§7.4 开篇）以及 `:8`（"把规划推到极致"）。

## 1. 原文的两分法

S&B 在 §8.8（纸面 p.181，PDF p.203）把"用模拟经验"分成两类，并给了两个名字：

> Used this way, planning is not focused on the current state. We call planning used in this way **background planning**.
> … Unlike the first use of planning, here planning focuses on a particular state. We call this **decision-time planning**.

区分标准是**规划的输出物**：

| | 背景规划 | 决策时规划 |
|:--|:--|:--|
| 触发 | 持续地、与当前状态无关 | 每遇到一个新状态就重做一次 |
| 输出 | 改进了的策略或价值函数（会被保存） | 单个动作 $a_t$（中间量通常丢弃） |
| 典型 | Dyna-Q 的 $n$ 步更新 | MCTS、启发式搜索、rollout 算法 |

同一章 §8.2（纸面 p.163，PDF p.185）里的 `search control` 是**背景规划内部**的一个环节，只负责"从哪些状态-动作对开始做模拟更新"：

> We use the term search control to refer to the process that selects the starting states and actions for the simulated experiences generated by the model.

## 2. 本章的用法

- `:20` 用了 `搜索控制`，含义与 S&B 一致（"规划要从已访问的状态-动作对里抽样"），**没有用错**。
- `:8` 把 §7.4 概括成"把规划推到极致：在博弈树上做搜索"，把 MCTS 也归到"规划"名下，**方向也对**（S&B 明确说 MCTS 是 decision-time planning）。
- 但全章没有一处写出"背景规划 / 决策时规划"这两个名字，也没有说明 `search control`（§7.1 的抽样环节）与树搜索（§7.4）是**两个不同层次的"搜索"**。

于是三处表述在读者眼里会连成一个环路：§7.1 说"搜索控制决定从哪些状态抽样"，§7.4 说"搜索在博弈树上做"，而两者恰好都用"搜索"二字。第 7.4 节的实验（图 7-6）又把"搜索预算增加"与"规划步数增加"并列比较，更容易被读成同一种东西。

## 3. 后果

这不是措辞洁癖，它改变对"规划收益"的理解：

- 背景规划把算力换成**更好的价值函数**，收益存在表里、可复用，代价是每次更新都离策略（模型想象的状态）；
- 决策时规划把算力换成**当前这一个决策**，收益只作用于此刻，代价是响应时间，而且中间结果通常丢弃。

本章第 7.5 节的取舍判据（"搜索成本 ≈ 模拟次数 × 单次前向"）只对决策时规划成立；对一个用 Dyna 做后台更新的系统，判据应是"每次真实交互能做多少次模型更新"。两类混在一起谈，判据就会错位。

## 4. 施工建议

1. 在 §7.1.1 末尾（`:22` 之后）加一句：Dyna 的这种规划叫**背景规划**，它与第 7.4 节的**决策时规划**（搜索）的区别是输出物——前者改价值与策略并保存，后者只产出当前动作。
2. 在 §7.4 开篇（`:175` 前）加一句回应：树搜索是决策时规划的一种，与 7.1 节的"搜索控制"不是同一件事——后者是背景规划里挑起点状态的环节。
3. 图 7-1 的图注可补半句"图中 `搜索控制` 指挑起点状态，不指树搜索"，避免与图 7-5 的"搜索"冲突。
