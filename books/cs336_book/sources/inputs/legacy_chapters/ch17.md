## 为什么多模态不是「再加一个编码器」

课程第 17 讲开门就把立场讲清楚了：

> "Transformers work really well. So we gotta use them. Transformers speak tokens (discrete or continuous), where a token represents some ~semantic unit of information. Therefore, we must convert everything into tokens."
> —— `lecture_17.py` 第 15–18 行

紧接着是一句限定：

> "Note: we had to do this with text (recall the tokenization lecture). For non-text modalities, this is more challenging..."
> —— `lecture_17.py` 第 19–20 行

第 1 章说过，BPE 分词是**可逆**的：encode 再 decode 必须还原原字符串。这条性质在多模态里立刻失效——图像不可能被无损地切成几百个 token，任何编码都是**有损压缩 + 语义选择**。所以"再加一个编码器"这个说法漏掉了真正的难点：编码器决定模型能看到什么，它看不到的东西，后面的 LLM 再大也补不回来。

课程把整讲压成两个问题：

> "1. How do we input non-text data (e.g., understand images)? 2. How do we output non-text data (e.g., generate audio)?"
> —— `lecture_17.py` 第 23–24 行

本章按这两个问题组织：先看输入怎么编码（CLIP、SigLIP），再看编码怎么注入 LLM（LLaVA 到 Qwen3-VL），然后看输出为什么必须换一套机制（Chameleon 的离散路线与 diffusion 的连续路线），最后讨论训练与评测上的差异——这是本讲与前面所有讲次最不一样的地方。

课程的总结第一句是行业判断，也是本章的前提：

> "Frontier models are expected to be multimodal (natively multimodal, omni)."
> —— `lecture_17.py` 第 41 行

这条判断在 2023 年之后的模型上已经兑现：GPT-4 从发布起就是多模态的 [@gpt_4_2023]，而 Llama 4 这类开放权重模型把"原生多模态"写进了架构前提 [@llama_4_2025]。所以本章讨论的不是"要不要做多模态"，而是"在哪一层把模态接进来"。

| 模态 | 表示 | 可逆性 | 一个 token 的含义 | 课程出处 |
| --- | --- | --- | --- | --- |
| 文本 | BPE 离散 id | 可逆（无损） | 子词片段 | 第 1 章；`lecture_17.py` 第 19 行 |
| 图像（理解） | 连续向量（ViT 特征） | 不可逆 | 一块 patch 的语义 | 第 74–78、154 行 |
| 图像（生成） | 离散码本 id（VQ-VAE） | 有损重建 | 一个码本条目 | 第 284–286 行 |
| 视频 | 帧序列 + 时间戳 | 不可逆 | 一帧的一块 patch | 第 221、248 行 |

同一个"图像"，在理解链路里是连续向量，在生成链路里是离散 id。这不是两种审美，而是两种需求的必然：理解要的是语义（能回答问题），生成要的是可采样（能逐 token 生成）。课程在总结里正是这么说的：

> "Comprehension and generation might demand different things (semantics versus finer-grained details)."
> —— `lecture_17.py` 第 43 行

## 对齐目标的共性：把一个 batch 变成分类问题

CLIP 的出发点很朴素：视觉模型一直在标注好的图像上训练，而互联网上有海量"图 + 说明文字"的弱标注对。

> "Question: is it possible to leverage the much larger amount of (image, caption) pairs?"
> —— `lecture_17.py` 第 54 行

方法是把一个 batch 变成分类问题：

> "Get a batch of (image, text) examples (e.g., 32768); Encode each image and each text; For each image, prefer its aligned text over other texts; For each text, prefer its aligned image over other images."
> —— `lecture_17.py` 第 57–60 行

写成式子就是 batch 内的对称 InfoNCE。设图像向量 $u_i$、文本向量 $v_j$，相似度取余弦，则图到文的损失是

$$
\mathcal{L}_{i\rightarrow t}=-\frac{1}{N}\sum_{i=1}^{N}\log
\frac{\exp(s_{ii}/\tau)}{\sum_{j=1}^{N}\exp(s_{ij}/\tau)},
\qquad
s_{ij}=\frac{u_i^{\top}v_j}{\lVert u_i\rVert\,\lVert v_j\rVert},
$$

文到图再对称地算一遍，两项平均。形状上要看清：$U\in\mathbb{R}^{N\times d}$、$V\in\mathbb{R}^{N\times d}$、$S\in\mathbb{R}^{N\times N}$，分母对**整行**做归一化。这一步的形状决定了一切工程后果——每一行都耦合了同 batch 的全部文本，所以 softmax 必须在全 batch 上算，课程把它列进 CLIP 的技术要求：

> "Technical: requires large batch sizes, softmax operation over full batch."
> —— `lecture_17.py` 第 95 行

batch 越大，每一行的负样本越多，任务越难、表征越好，但通信与显存也越贵（第 7 章的 all-gather 在这里重新出现）。

SigLIP 换掉的就是这一步：

> "CLIP: multiclass classification for (text, image) versus (text, image') for all image'. SigLIP: binary classification for (text, image) - aligned or not?"
> —— `lecture_17.py` 第 101–104 行

于是损失从"行内 softmax"变成"逐元素 sigmoid + 标签"：

$$
\mathcal{L}_{\text{SigLIP}}=-\frac{1}{N}\sum_{i=1}^{N}\sum_{j=1}^{N}\log\sigma\big(z_{ij}\,s_{ij}\big),
\qquad
z_{ij}=\begin{cases}+1,& i=j\\ -1,& i\ne j\end{cases}
$$

差别不是换个损失函数那么小。softmax 版本里每个样本的梯度依赖整行（要用到全部 $N$ 个负样本的归一化项），sigmoid 版本里每一项 $(i,j)$ 都是独立的二分类，归一化被拆掉了。课程给出的直接结论是：

> "Decouple batch size from loss. Better than CLIP for <16K batch sizes. Go up to 1M batch size, but 32K is enough."
> —— `lecture_17.py` 第 119–121 行

课程还给了一组效率对照：CLIP 用 256 块 TPUv3 训 10 天，SigLIP 用 32 块 TPUv4 训 5 天（第 114–115 行）。这个对比不是同一硬件下的公平 benchmark（TPUv4 的峰值算力更高），但量级差足以说明"损失形状 → 并行策略 → 成本"这条链是真实的。

| 维度 | CLIP（`lecture_17.py` 57–60、95） | SigLIP（101–121） |
| --- | --- | --- |
| 任务形式 | 行内多分类（1 正 $N-1$ 负） | 逐对二分类（对齐/不对齐） |
| 归一化范围 | 整行（跨样本耦合） | 无（每对独立） |
| 对 batch 的依赖 | 必须大 batch 才有足够负样本 | 可与 batch 解耦，小 batch 也可用 |
| 课程给的效率数字 | 10 天 / 256 TPUv3 | 5 天 / 32 TPUv4 |
| 一句话总结 | 强，但贵 | 便宜，且够好 |

两者共享的"对齐目标"可以一句话概括：**在表示空间里让配对样本相似度上升、非配对下降**。这是所有模态对齐的共同骨架——CLIP 与 SigLIP 的差别只在"非配对怎么算"，而这个差别完全由损失形状决定。

## 注入：连接器就是信息瓶颈

有了图像向量，下一步是把它塞进语言模型。LLaVA 的做法简单到近乎粗暴：

> "Encode images with CLIP (ViT-L/14); Linear projection (W) into embedding space (Flamingo and Q-former are more complex)."
> —— `lecture_17.py` 第 137–140 行

也就是

$$
E_{\text{img}}=f_{\text{ViT}}(I)\in\mathbb{R}^{n\times d_v},
\qquad
X_{\text{vis}}=E_{\text{img}}W\in\mathbb{R}^{n\times d},
\qquad
X_{\text{in}}=\big[\,X_{\text{vis}};\ X_{\text{txt}}\,\big],
$$

其中 $W\in\mathbb{R}^{d_v\times d}$ 是唯一可训练的新参数，$[\cdot;\cdot]$ 表示沿序列维拼接。文本 token 与视觉 token 从此在同一个序列里，走同一个 attention——这就是"多模态"在实现层面的全部含义。

每张图产生多少个 token，是个必须先算的量。（教材补全）CLIP 的最佳配置是 ViT-L/14@336px（第 78 行），即 14×14 的 patch、输入 336×336，于是

$$
n=\left(\frac{336}{14}\right)^{2}=24^{2}=576 .
$$

576 个 token 只换一张图，而一段 500 字的文本大约 700 个 token——图像的信息密度与文本完全不在一个量级上。这就是后面所有"压缩"动作的动机：Qwen-VL 用一层 cross-attention adaptor 把任意分辨率压到**固定 256 个 token**（第 200 行），Qwen2-VL 则先用 ViT/14 切 224×224，再把 2×2 邻域合并：

$$
n=\left(\frac{224}{14}\right)^{2}\Big/\,2^{2}=256/4=64\ \text{（课程记为 }66\text{）},
$$

（教材补全）这里 64 与课程给的 66 差 2，按算术反推是额外 2 个边界/特殊 token；课程只给了结果，没给这个加法，所以这 2 个 token 的归属属于本书的推断，不应被当作课程结论。

分辨率的处理是另一条主线。CLIP 的预处理是"短边缩到 336 再中心裁剪"（第 69–72 行），这意味着长图的两端会被切掉。LLaVA-OneVision 用 AnyRes 解决：

> "Preserving high resolution is important (e.g., for OCR); CLIP resizes and crops to 336x336, which loses information; Solution: AnyRes ... Break up image into a x b pieces (matching resolution of vision encoder), encode, concatenate; If too many tokens (original image is too high resolution), then use bilinear interpolation."
> —— `lecture_17.py` 第 159–164 行

AnyRes 的本质是"用 token 数换分辨率"：块数 $a\times b$ 越多，细节保留越多，序列越长。于是 token 预算成了唯一的设计货币，课程在讲 OneVision 处理三类输入时把它说得很直白：

> "Goal: make all of the modalities produce roughly the same length. Single image: use higher resolution; Multiple images: use base resolution for each image; Video: use lower resolution for each frame."
> —— `lecture_17.py` 第 166–170 行

同一套权重，喂一张图就用高分辨率，喂 20 张图就降分辨率，喂视频就再降——不是因为模型喜欢这样，而是因为显存与 attention 的 $O(T^2)$ 不允许 token 数随输入线性膨胀。

| 模型 | 视觉编码器 | 连接器 | 每图 token（课程数字） | 出处 |
| --- | --- | --- | --- | --- |
| LLaVA | CLIP ViT-L/14 | 单层线性投影 | 576（由 336/14 算出，教材补全） | 第 137–140 行 |
| LLaVA-OneVision | SigLIP（末层前后 grid 特征） | 2 层 MLP | 随 AnyRes 的 $a\times b$ 变 | 第 154–164 行 |
| Qwen-VL | OpenCLIP ViT-bigC/14 | 单层 cross-attention + 2D 位置编码 | 固定 256 | 第 198–201 行 |
| Qwen2-VL | 675M ViT | 2×2 邻域合并 | 66（动态分辨率） | 第 216–221 行 |
| Qwen3-VL | SigLIP-2 | DeepStack 跨层融合 | 随分辨率与帧数变 | 第 244–252 行 |

连接器的"深度"是一个容易被忽视的设计维度。LLaVA 只用一层线性投影（第 139 行），Qwen-VL 用一层 cross-attention（第 200 行），OneVision 用两层 MLP（第 156 行），Qwen3-VL 用 DeepStack 往多个层里注入（第 252 行）。（教材补全）这四种做法的差别可以这样理解：线性投影只改变基，不改变 token 数与容量；cross-attention 能把任意长度的视觉特征压到固定 256 个 token，是"压缩器 + 对齐器"二合一；MLP 比线性多一层非线性，能拟合更复杂的映射；DeepStack 则是把视觉信息同时送进低层与中层——因为若只在第一层注入，后面几十层只能通过自注意力的间接路径反复搬运视觉信息，深层注入等于给模型一条更短的梯度通路。课程把这句写在 OneVision 小结里："vision encoder + projector + LM" 是标准模板（第 190 行），模板相同，这些细节决定了上限。

模板之外的另一个变量是"换多大的语言模型"。OneVision 直接把解码器换成 Qwen-2 72B [@qwen_2_5_2024]（第 155 行），而 Qwen3-VL 建立在 Qwen3 上（第 241 行，含 dense 与 MoE 两条线，最大到 235B-A22B）[@qwen_3_2025]。这说明视觉侧与语言侧的规模是**解耦**的：视觉编码器通常停在几百 M 到一两 B（Qwen2-VL 的 ViT 是 675M，第 217 行），而语言侧可以继续放大。多模态的"扩容"主要发生在语言侧，视觉侧靠分辨率与 token 数扩容——这也是为什么 token 预算值得单独讨论。

Qwen3-VL 的两处改动值得注意，因为它们都指向"位置信息怎么编码"这个更深的问题。其一是交错 MRoPE：课程把时间、宽、高三个轴交替分配到低高频段，写成 `[t w h t w h ...]` 而不是 `[t t t t w w w w h h h h]`（第 246–247 行）。其二是把视频时间戳做成**显式 token** 而不是编码进位置（第 248 行）——位置编码表达的是"相对远近"，而时间戳表达的是"第几秒"，后者是绝对量，塞进位置编码会被 RoPE 的相对性抹掉。（教材补全，依据 RoPE 只编码相对位移这一性质。）

这一整套"编码器 + 连接器 + LM"的模板在图 17-2 里画成了一条流水线。图中三个数字（576、256、66）分别对应 LLaVA 的算术结果、Qwen-VL 的固定长度、Qwen2-VL 的合并结果——它们是同一张图在不同设计下被允许占用的 token 数，也是理解这个领域所有取舍的入口。

## 对齐目标的分歧：语义对齐与重建对齐

前面两节用了两次"对齐"，但指的是两件不同的事，必须分开。

CLIP/SigLIP 学的是**语义对齐**：让图像表示靠近它的说明文字。监督信号来自 caption，而课程把这层监督的性质说得很清楚：

> "Encoding of images captures semantics given by (noisy) text. Design decisions chosen based on image classification (not very fine-grained)."
> —— `lecture_17.py` 第 93–94 行

这句话里有两个限定词值得划重点：**noisy**（网上的说明文字常常写错、常常只描述了图的一部分）与 **not very fine-grained**（取舍是按图像分类这类粗粒度任务做的，不是按 OCR 这类细粒度任务做的）。所以 CLIP 特征天生擅长"草地上有一只猫"，天生不擅长"第三行第二个字是 7"。

VQ-VAE 学的是**重建对齐**：让解码后的图像逼近原图。

> "Idea: map image to a discrete codebook, decode back to image and minimize reconstruction loss."
> —— `lecture_17.py` 第 282 行

（教材补全）它的目标是标准的重建误差：

$$
\mathcal{L}_{\text{VQ}}=\big\lVert I-D\big(z_{q}(E(I))\big)\big\rVert_{2}^{2},
$$

其中 $E$ 是编码器、$z_q$ 是量化到码本、$D$ 是解码器。课程只给了 "minimize reconstruction loss" 这个说法，这个式子是它的标准写法。注意它**完全没有文本参与**：VQ-VAE 不知道"猫"是什么，只知道哪些像素该是什么颜色。

| 维度 | 语义对齐（CLIP / SigLIP） | 重建对齐（VQ-VAE） |
| --- | --- | --- |
| 监督信号 | (图, 说明文字) 对，含噪声 | 像素本身，无噪声 |
| 学到什么 | 类别级、场景级语义 | 低层纹理与边缘 |
| 丢失什么 | 细粒度细节、文字笔画 | 语义（不知"这是什么"） |
| 输出 | 连续向量（不可解码回图） | 离散码（可解码回图） |
| 课程依据 | 第 93–94 行 | 第 282、297 行 |
| 典型用途 | 理解 | 生成 |

这张表解释了为什么"一个编码器通吃"行不通：两个目标的梯度指向不同方向，语义对齐会把细节压掉（细节对"图文匹配"这个任务没用），重建对齐会把语义丢掉（语义对"像素误差"没有贡献）。Chameleon 的"统一离散"本质上是在两者之间做折中：用 VQ token 让模型能生成，代价是理解侧要忍受离散化损失——这就是课程说它 "not as performant" 却仍称其 "elegant"（第 296–297 行）的原因。

所以更常见的工程答案是**分工**：理解走连续编码器（CLIP/SigLIP），生成走 diffusion（第 45 行）。这条路线牺牲了"一个模型统一所有模态"的美感，换来每一项指标都不妥协。

## 输出非文本：连续解码还是离散自回归

前面所有模型都有一个共同缺陷：只能读，不能画。

> "So far: VLMs encode images (via CLIP or SigLIP), inject into LM. Disadvantage: can't generate images (need diffusion). Chameleon: map everything into discrete tokens. Advantage: can analyze and generate images in a uniform way."
> —— `lecture_17.py` 第 271–275 行

Chameleon 的路线是"一切皆 token"，因此必须有一个**能输出离散 token 的图像编码器**：

> "VQ-VAE (Vector Quantized Variational Autoencoder). Idea: map image to a discrete codebook, decode back to image and minimize reconstruction loss. Encodes 512 x 512 image into 1024 tokens (codebook of size 8192). Train a new BPE tokenizer."
> —— `lecture_17.py` 第 281–286 行

（教材补全）算一下这条路的压缩率，就能看出它为什么必然丢信息。一张 512×512 的 RGB 图原始是 $512\times512\times3=786{,}432$ 字节；VQ-VAE 把它变成 1024 个、每个 13 bit 的码本索引，共

$$
1024\times\log_2 8192=1024\times13=13{,}312\ \text{bit}\approx1.66\ \text{KB},
$$

压缩比约

$$
\frac{786{,}432\times8}{13{,}312}\approx473 .
$$

473 倍的压缩不可能无损，损失的正是高频细节——课程用一句话点破了后果：

> "Not as performant (discretization loses information - think OCR)."
> —— `lecture_17.py` 第 297 行

离散化对 OCR 最致命，因为文字识别靠的恰恰是高频笔画细节；而语义类问答对此不敏感。这就把第 1 章"分词"的直觉推到了极限：文本的 token 化可以做到无损，图像的 token 化做不到——**损失多少、损失在哪里，是编码器的设计选择，而不是实现细节**。

代价还体现在训练稳定性上，这是 Chameleon 一节最有价值的部分：

> "Text tokens have low entropy, image tokens have high entropy, leads to norm growth, logit drift problem. Fixes: QK norm, z-loss regularization."
> —— `lecture_17.py` 第 291–293 行

（教材补全）机制可以这样读：文本下一个 token 的分布很尖（低熵），图像下一个 token 的分布很平（高熵，8192 个码本条目里挑一个）。若两类 token 共享同一套输出层与残差流，图像的损失会持续把 logit 的尺度往上推，于是残差范数增长、softmax 的 logit 漂移——这是"两种熵混在一个模型里"的直接后果。课程给的两个修法都是压尺度：QK norm 把 attention 的 $QK^{\top}$ 归一化，z-loss 惩罚配分函数的对数：

$$
\mathcal{L}_{z}=\lambda\,\big(\log Z\big)^{2},
\qquad
Z=\sum_{v=1}^{V}\exp(o_v),
$$

其中 $o_v$ 是输出 logit。（教材补全，依据是课程只给了 "z-loss" 这个名字；$(\log Z)^2$ 这一形式来自把 softmax 配分函数钉在 0 附近的标准做法。）

课程的收官判断把两条路线并列保留：

> "Continuous encoders + Transformer + diffusion models for generation."
> —— `lecture_17.py` 第 45 行

也就是说：理解侧继续用连续编码器（CLIP/SigLIP 之类），生成侧交给 diffusion；Chameleon 的"统一离散"路线优雅但有代价。这不是谁取代谁，而是"语义"与"细节"两个需求在架构上的分工。

## 训练与评测的差异

多模态章节与前面所有章节最大的不同，是**同一个模型在不同训练阶段会冻结不同的部分**。这不是调参偏好，而是"先对齐表示、再联合优化"的顺序约束。

| 模型 | 阶段 1 | 阶段 2 | 阶段 3 | 出处 |
| --- | --- | --- | --- | --- |
| LLaVA | 冻结视觉编码器与 LM，只训 $W$ | 冻视觉编码器，训 $W$ + LM | — | 第 143–144 行 |
| Qwen-VL | 大规模低质数据；冻 LM，训编码器 + adaptor | 高质量任务数据、提分辨率；全参训练 | 指令数据；冻视觉，训 adaptor + LM | 第 205–209 行 |
| Qwen2-VL | 只训视觉编码器 | 全参训练 | 指令跟随数据上训 LM | 第 228–230 行 |
| Qwen3-VL | 预训练四阶段：adaptor → 8K → 32K → 256K 长度 | （同左，逐段放开） | 后训练：SFT 长 CoT + 蒸馏 + RL | 第 254–257 行 |

（教材补全）这张表有两条可读的规律。第一，**第一阶段几乎总是"只训连接器"**：LLaVA 只训 $W$、Qwen-VL 只训编码器与 adaptor。此时梯度只经过新参数，最大的风险是把已经训好的语言能力冲掉，所以冻结是对的。第二，**训练顺序跟随上下文长度**：Qwen3-VL 从 8K 到 32K 再到 256K（第 255 行），因为长序列的 attention 成本随 $T^{2}$ 增长，先用短序列把表示对齐、再用长序列扩展，比一上来就 256K 便宜得多。

数据侧的共同经验只有一句，但分量很重：

> "Most work goes into data curation (heavy on synthesized, task-specific data)."
> —— `lecture_17.py` 第 191 行

LLaVA 的 158K 样本是拿 MS COCO 的标注喂给 GPT-4 生成问答再配回原图（第 130–134 行）；OneVision 明确说"quality over quantity"（第 173 行）。这与第 13、14 章的数据工程结论一致：多模态的瓶颈不在模型结构，而在"图 + 指令 + 正确答案"这种三元组的供给。

评测上的差异更隐蔽，也是本章必须点明的地方。文本评测里，同一道题喂给模型就是同一串 token；多模态评测里，**同一张图经过不同预处理会变成不同长度的 token 序列**——短边缩到 336 再中心裁剪（第 69–72 行）会丢掉长图两端，AnyRes 切块（第 159–164 行）会把同一张图变成 $a\times b$ 倍的 token，视频还要先定采样率（第 221 行：2 帧/秒、上限 16384 token）。输入的信息预算变了，分数就不可比。

| 能力 | 依赖的输入预算 | 课程依据 | 预算不足时的失效方式 |
| --- | --- | --- | --- |
| 图像分类 / 场景理解 | 低（一张 336×336 就够） | 第 74–78 行 | 几乎不受影响 |
| OCR / 文档理解 | 高（分辨率即信息） | 第 159–160 行 | 小字糊成一块，答案凭空猜 |
| 图表 / 多图关系 | 中高（要保留图间结构） | 第 166–170 行 | 张冠李戴，指代错图 |
| 视频时序 | 采样率决定时间分辨率 | 第 221、248 行 | 漏掉短事件，或时间戳对不上 |
| 视觉定位 | 高（要空间坐标） | 第 198–201 行（`<box>`、2D 位置编码） | 框位置系统性偏移 |

所以读多模态论文时要先问一句：它的 token 预算给了多少？两个模型在"OCR 分数"上的差距，可能只是其中一个把图切得更细。（教材补全）这也是本章把"定量评测结论"放进未覆盖清单的原因——课程没有给统一口径的 benchmark 数字，本书不替它编一个。

还有一层更根本的错配：**训练用教师强制，评测用自由解码**。训练时每个位置喂的是真实前缀，模型只需在已知上下文上预测下一个 token；评测时模型吃的是自己上一步的输出，一旦前面错一个 token，后面就在错误的上下文里继续。文本任务里这个差距通常被 SFT 抹平，多模态任务里它被放大——因为视觉 token 的错误不是"选错词"而是"看错位置"，而位置错误会改变整段视觉上下文的含义。（教材补全，依据是自回归训练的 teacher forcing 与推理时的自由运行这一对设定；课程未讨论此点。）

### 训练不稳定的两个来源

第一个来源是前面说的熵差（第 291–293 行）：文本低熵、图像高熵，混在一个输出层里会让 logit 尺度失稳。修法是 QK norm 与 z-loss。

第二个来源是**样本长度极不均匀**。视频样本动辄上万 token，文本样本几百 token，若按 token 平均，一个 batch 的损失会被视频主导。Qwen3-VL 的修法写得很具体：

> "Square-root-normalized per-token loss: balance text and multimodal data (video examples are long, don't want to dominate)."
> —— `lecture_17.py` 第 249 行

（教材补全）写成式子，设模态 $m$ 有 $n_m$ 个 token、逐 token 损失 $\ell_t$，则

$$
\mathcal{L}=\sum_{m}\frac{1}{\sqrt{n_{m}}}\sum_{t\in m}\ell_{t},
$$

与"按 token 平均"（$1/n_m$）相比，$\sqrt{n_m}$ 只是部分抵消长度：长样本仍然贡献更多，但不再是线性主导。选 $\sqrt{\cdot}$ 而不是别的幂次，本质是在"完全平均（每个样本等权）"与"完全按 token（每个 token 等权）"之间取一个折中——课程给了这个做法，没给推导，所以这里的解释属于教材补全。

## 本章小结

- 多模态的第一性问题是"怎么把非文本变成 token"，而这一步是有损的；文本分词可逆，图像编码不可逆。
- 对齐目标有共同骨架：让配对样本在表示空间靠近、非配对远离。CLIP 用行内 softmax，SigLIP 用逐对 sigmoid；后者把 batch 与损失解耦，便宜得多。
- 注入的关键是连接器与 token 预算：线性投影（LLaVA）、固定 256 token（Qwen-VL）、2×2 合并到 66 token（Qwen2-VL）、AnyRes 与统一长度（OneVision）、DeepStack 与交错 MRoPE（Qwen3-VL）。
- 生成侧分两条路：连续编码器 + diffusion，或 VQ-VAE 离散化 + 自回归（Chameleon，约 473 倍压缩，必然丢细节，OCR 最敏感）。
- 训练差异在"冻结什么、按什么顺序放开"；评测差异在"输入的信息预算"，预算不同的分数不可直接比较。
- 稳定性问题来自两处：模态间熵差（QK norm、z-loss）与样本长度不均（$\sqrt{n}$ 归一化）。

**自测**：一张 512×512 的 RGB 图用 VQ-VAE 编码成 1024 个 token、码本 8192，问每图多少 bit、相对原始 8 bit RGB 压缩多少倍；再问 ViT-L/14@336px 会把一张 336×336 的图切成多少个 token。（答案：$1024\times\log_2 8192=13{,}312$ bit ≈ 1.66 KB；原始 $512^2\times3\times8=6{,}291{,}456$ bit，压缩约 473 倍。ViT-L/14 的 patch 为 14×14，$336/14=24$，故 $24^2=576$ 个 token。）
